# Support

This page explains where to take a question so it reaches the right process.

## Bug

Something in the **documentation** is wrong, contradictory, or unclear, or (later) the **application** misbehaves.

Use a [Bug report](https://github.com/DouglasPrado/ushark/issues/new?template=bug_report.yml).

Include reproduction steps. Strip secrets from logs.

## Feature request

You want behavior that is missing from the specs or from a future implementation.

Use a [Feature request](https://github.com/DouglasPrado/ushark/issues/new?template=feature_request.yml).

Check [docs/](docs/README.md) and [ROADMAP.md](ROADMAP.md) first; the change may already be specified.

## Discussion

Open-ended design conversation (naming, UX trade-offs, architecture alternatives) that is not yet a concrete bug or request.

Use GitHub Discussions **if that feature is enabled** on the repository. Otherwise use an issue and label it as a discussion, or comment on an existing related issue.

## Security issue

A vulnerability, secret leak, or trust-boundary bypass.

**Do not** use a public issue. Follow [SECURITY.md](SECURITY.md).

## Usage question

“How do I run / install / configure this?”

Today there is no application to run. Read [README.md](README.md) and [docs/README.md](docs/README.md).

When the app exists, prefer Discussions (if enabled) or a usage issue rather than a bug report, unless you have a failing reproduction.

## Conduct

Harassment or CoC violations: [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), reported privately.
